# Versioning foundation — A2

Use MAJOR.MINOR.PATCH semantic versioning:

- MAJOR: breaking runtime or governance change.
- MINOR: compatible feature or capability expansion.
- PATCH: fix, clarification, or non-breaking correction.

The current development target in root VERSION is 1.0.0-dev. The approved progression is 1.0.0-dev → 1.0.0-rc1 → 1.0.0. A repository date does not establish a release version. Promotion requires the applicable qualification and approval evidence.

Pin component versions independently and bind the release manifest to their exact versions and source commit. Record changes under Added, Changed, Fixed, Deprecated, Removed, Security and Governance in CHANGELOG.md. Describe governance changes explicitly and use the change-control process for affected authority or controls.

This documentation does not promote a release or activate runtime execution.
